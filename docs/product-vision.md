# 个性化学习推荐系统产品理念与定位

> 本文只谈**产品是什么、为谁、边界在哪、为什么这样取舍**。技术架构见 `architecture.md`，开发路线与进度见 `roadmap.md`。三者分工：vision 讲“为什么这么做”，architecture 讲“怎么搭”，roadmap 讲“做到哪、下一步做什么”。
>
> 理念确立于 2026-09-16，源自一批测试人员反馈引发的产品定位协商。

## 项目性质与边界（理解一切取舍的前提）

本项目定位为**比赛作品 + 学习载体**，不是真要商业化上线、放开给公众使用的产品：

- **目标一（比赛）**：一套完整的产品架构 + 有深度的产品思考 + 扎实的工程实现。
- **目标二（学习与就业）**：完整走一遍产品从 0 到 1 的架构搭建，并真实跑通深度学习 / 微调的专业知识，为就业积累可展示的硬技能。
- **明确不追求**：真实用户规模、留存率、商业化增长。

由此推出一条贯穿全文的取舍原则：**凡属“真上线运营”才需要解决的事（冷启动破局、内容库规模化、用户增长、留存运营），本项目想清楚、写下来，但不实做。** 这不是能力缺口，而是主动划的边界——知道“该做什么、不该做什么、为什么”，本身就是产品成熟度，也正是比赛与面试要展示的东西。

## 一句话定位

一个通过多轮对话了解你当前学习情境、从策略知识库召回合适的学习方法、并给出**有研究出处、可解释、可反馈**的个性化推荐的**学习教练**。

它教的是“怎么学”（方法），不是“这道题的答案”（内容）。

## 初心

让经过验证的好方法被传承下来。知识库主体来自用户投稿，权威文献（如 Dunlosky 等人 2013 年的综述）只作冷启动种子与对照基线，不是内容主体。投稿一律人工审核、先小范围投放、按真实反馈升降权——机制详见 `architecture.md`《用户投稿与渐进投放》。

## 产品困境：为什么“光给策略”会被觉得没用

2026-09-16 的测试反馈里，**多数人第一反应**是“单纯给学习策略没用”，想要“一个能讲解知识的东西”。诊断下来是三道鸿沟：

1. **抽象层错位**：用户带着“内容层”的痛点来（这道题不会、这个记不住），系统给的是“元层”的方法（你该用间隔重复）。
2. **即时价值缺失**：学习方法的价值是长期、延迟的（用了以后学得好），用户要的却是当下见效（我现在就搞定）。延迟的价值很难被感知成“有用”。
3. **可操作性差**：只给方法名，没给“怎么把它用到我手头这个具体东西上”。

一句话概括：**你在授人以渔，可饿肚子的人先想要鱼。**

## 抉择：拒绝 A（通用答疑），坚持 B（学习教练）

“想要能讲解知识的东西”有两种截然不同的解读：

- **A —— 讲学科内容**（“帮我讲这道高数题”“讲讲光合作用”）：这是要变成通用答疑 AI。
- **B —— 讲方法本身 + 示范怎么用在我的内容上**（“间隔重复到底怎么操作？拿我这 20 个单词示范一遍”）：这仍是学习教练。

**决策：拒绝 A，坚持 B。** A 是红海——没有学科内容库、一个人做不过 ChatGPT / 作业帮、还会丢掉“教方法”的初心与差异化护城河。B 守得住初心，且市面上“有研究证据 + 用户投稿传承 + 细到题型级讲解”的学习方法产品几乎没人做，是蓝海。

## 理念升级：先给鱼，再教渔（A 入口、B 交付）

坚持 B 不等于上来就甩方法。正确的顺序是**先用鱼把人接住，他吃着鱼的时候把渔教了**：

- **入口层用 A 的形态接住用户**：“把你正在头疼的东西丢给我——一道题、一个记不住的知识点都行。”
- **交付层用 B 的内核**：“我带你搞定它，顺手教你怎么搞定这一类。”

本质：**以 A 为钩子，以 B 为货。** 用户要的是鱼（答案 / 即时帮助），你给的是渔（方法），但必须现场示范怎么捕到这条鱼。所以“多数人要 A”是**入口要像 A** 的理由，不是**产品要变成 A** 的理由。

**适用边界**：A 入口 B 交付是冷启动期与用户教育阶段的打法；等库里积累了足够多题型级细粒度策略，就能直接推荐具体方法，A 的钩子逐渐让位给 B 本身。

## 策略粒度下沉：B 的天然燃料

现有 13 个策略都是“大方向”的通用元认知方法（间隔重复、自我解释……，10/13 精确对应 Dunlosky 十项技术），离具体内容远，所以显空。但用户投稿的策略会越来越细：

**通用级 → 学科级 → 知识点级 → 题型级**（从“怎么学数学”到“圆锥曲线怎么练”到“定语从句怎么记”）。

关键洞察：**策略越细，它本身就越有内容、越可讲、越可示范。** 一个“圆锥曲线解题套路”的 `definition` / `procedure` 天然就是半堂学科课。当策略下沉到题型级，“讲解式推荐”本身就在讲知识了——讲的是“方法性的知识”，不是题库答案。**B 因此会自动长出一部分 A 的质感**，治好“觉得没用”，却完全不碰通用答疑。

## B 的两个形态升级

1. **讲解式推荐**：每条推荐从“一张卡片”变成“一段像老师讲课的内容”——这方法是什么（`definition`）、凭什么有效（`evidence` + 可点开 DOI）、具体几步（`procedure`）、适合你这情况吗（`suitable_condition` / `unsuitable_condition`）。**素材库里五类 chunk 已经齐了**，缺的只是把它们组织成“一堂小课”的呈现形态。
2. **示范式讲解**：让用户丢一个“正在学的具体东西”进来（一道题、一个知识点），系统当场用推荐的策略示范一遍。这一步把渔和鱼缝在一起。

## 诚实记录：冷启动死结（想清楚了，有意不做）

“A 入口 B 交付”有个前置刚需——**库里要有足够多“学科 / 题型级”的细粒度策略**，否则用户丢一道圆锥曲线题进来，系统只能甩“间隔重复”，又回到“没用”。而这撞上一个鸡生蛋死结：

> 好体验 ← 需要细粒度策略 ← 需要用户投稿 ← 可用户觉得没用就不投稿。

破局路径想清楚了（① 种子策略先行，手工造高频学科 / 题型；② 用 LLM 学科能力当示范载体；③ 入口话术与 onboarding 重设计），但**它们全属“真上线商业化”范畴，按本文开头的项目性质，本项目不实做**，只在此记录，以证明“想到了、也知道为什么现在不做”。

## 两条线，各喂一个目标

| 线 | 做什么 | 喂哪个目标 | 深度 |
| --- | --- | --- | --- |
| **理念线**（本文档） | 把产品思考沉淀成清晰的理念与边界 | 比赛（路演素材、产品思维） | 轻量，写清楚即可 |
| **专业线** | 深度学习模型真跑一遍（三个预留模型见 `roadmap.md` 阶段 7–9） | 就业（微调 / RAG / 训练硬技能） | 实做，跑通流程 |

两条线不冲突、互为补充：理念线展示“想得清”，专业线展示“做得出”。专业线的目标是**完整跑通“数据 → LoRA 微调 → 评估 → 推理”、学到东西、面试讲得清**，不是把模型做到能上线替换现用的第三方模型——同样遵循“为学习，不为上线”。

## 已实现 vs 有意未做

**已实现的核心链路**（详见 `roadmap.md`《当前已经完成》）：episode 情境化画像、多轮对话推荐链路、治理闸门与渐进投放执行层、evidence 研究出处、流式回复、人工审核端点、日志脱敏与保留期。

**有意未做的演进方向**（详见 `roadmap.md`《暂不优先》与阶段 7–9）：A 入口 B 交付的完整产品形态、策略粒度下沉的标签与召回、讲解式 / 示范式推荐、冷启动破局、投稿接口与审核界面、两个自研深度学习模型的上线替换。

**“有意未做”不是待偿的技术债，而是基于项目性质（比赛 + 学习、不商业化上线）的主动取舍。**
